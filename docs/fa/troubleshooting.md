# عیب‌یابی

این صفحه را از بالا به پایین جلو بروید: بخش اول رایج‌ترین مشکلات است.

قبل از هر کاری، از منوی اصلی برنامه گزینهٔ **Check receiver requirements** را
بزنید. این گزینه `ffmpeg`، کلید API، شبکه، پورت‌ها و فضای آزاد را بررسی می‌کند و
با زبان ساده می‌گوید چه چیزی کم است.

---

## پخش

### هیچ‌چیز پخش نمی‌شود — صفحه سیاه می‌ماند

۱. تنظیمات را باز کنید (**INFO**) و **Default Live Stream Type** را روی
   `5002 (exteplayer3)` بگذارید. همین یک کار بیشتر موارد را حل می‌کند، مخصوصاً
   روی DreamOS.
۲. اگر فیلم پخش می‌شود ولی کانال زنده نه (یا برعکس)، یادتان باشد دو تنظیم جدا
   وجود دارد: *Default Live Stream Type* و *Default VOD Stream Type*.
۳. مطمئن شوید `ffmpeg` نصب است: با SSH بنویسید `ffmpeg -version`. اگر نبود، با
   `opkg install ffmpeg` یا `apt-get install ffmpeg` نصبش کنید.

### پلی‌لیست بارگذاری نمی‌شود

از منوی اصلی برنامه **Test playlists** را بزنید. آدرس هر پلی‌لیست (با رمز پنهان)،
کد HTTP و پاسخ سرور را نشان می‌دهد. بعد:

| کد | یعنی | چه کنید |
|---|---|---|
| `401` | نام کاربری یا رمز غلط است | مشخصات اشتراک را بررسی کنید |
| `403` | سرور شما را بلاک کرده | برنامه خودکار با شناسهٔ یک پخش‌کنندهٔ معمولی دوباره امتحان می‌کند؛ اگر باز هم نشد آدرس را در مرورگر تست کنید — بعضی سرویس‌دهنده‌ها بر اساس کشور یا دستگاه بلاک می‌کنند |
| `404` | آدرس غلط است | لینک به‌روز را از سرویس‌دهنده بگیرید |
| `429` | درخواست بیش از حد | چند دقیقه صبر کنید؛ به سقف سرویس‌دهنده خورده‌اید |

### تصویر یخ می‌زند یا می‌پرد

- **Stream bitrate while translating** را روی `1.5 Mbit/s` بگذارید.
- نوع استریم را `5002 (exteplayer3)` امتحان کنید.
- ببینید با ترجمهٔ **خاموش** (دکمهٔ قرمز) هم می‌پرد یا نه. اگر باز هم می‌پرد،
  مشکل از خود استریم یا اینترنت شماست، نه از ترجمه.

### تصویر هر چند دقیقه برای چند ثانیه قطع می‌شود

دیکدر رسیور لحظه‌ای استریم محلی را گم کرده و دوباره وصل شده است. نسخهٔ ۱.۰ بافر
دیکدر را به ۵ ثانیه رسانده تا وقفه‌های کوتاه را ببلعد. اگر باز هم دیدید، ساعتش
را یادداشت کنید و همان لحظه را در `/tmp/piip_dub.log` ببینید — خط
`Native Enigma2 HTTP/TS client connected` نشانهٔ هر بار وصل شدن دوباره است.

---

## ترجمه

### اصلاً ترجمه نمی‌آید

۱. روشن است؟ دکمهٔ **قرمز** در حین تماشا، یا *Translation enabled* در تنظیمات.
۲. کلید سر جایش هست؟ با SSH: `wc -c /root/apikey.txt` باید حدود ۴۰ چاپ کند.
۳. گزینهٔ **Check receiver requirements** را بزنید.
۴. لاگ را ببینید: `tail -30 /tmp/piip_dub.log`. خطی که در آن `401` یا `403`
   باشد یعنی کلید غلط است یا برای Gemini API فعال نشده.

### شروع می‌شود ولی بعد از چند دقیقه قطع می‌شود

معمولاً سقف مصرف یا مسئلهٔ پرداخت در حساب گوگل. مصرفتان را در
<https://aistudio.google.com> ببینید. دلیلش در لاگ هست:

</div>

```bash
grep -i "retrying\|quota\|denied" /tmp/piip_dub.log | tail
```

<div dir="rtl">

### ترجمه از تصویر عقب است

چند ثانیه عقب بودن طبیعی و اجتناب‌ناپذیر است — بخش *یک نکته دربارهٔ تأخیر* در
[شروع از صفر](getting-started.md) را ببینید.

اگر خیلی بیشتر عقب افتاد، برنامه خودش اصلاح می‌کند: تقریباً هر یک دقیقه برای
لحظه‌ای تغذیهٔ صدا را قطع می‌کند تا موتور به تصویر برسد. در آن لحظه یکی‑دو جمله
ترجمه نمی‌شود. مقدار اندازه‌گیری‌شده در لاگ هست:

</div>

```bash
grep "Audio flow" /tmp/piip_dub.log | tail -5
```

<div dir="rtl">

عدد جلوی `drift=` یعنی ترجمه چند ثانیه عقب بوده. زیر حدود ۱۰ طبیعی است. اگر
می‌خواهید چسبیده‌تر بماند، *Max backlog* را در تنظیمات کم کنید — به قیمت اینکه
جمله‌های بیشتری جا بیفتد.

### صدای ترجمه قطع و وصل می‌شود

تأخیر برای اینترنت شما کم است. با دکمهٔ **سبز** در حین تماشا، یا گزینهٔ *Delay*
در تنظیمات، زیادش کنید.

### آواز و موسیقی بی‌معنی ترجمه می‌شود

طبیعی است. مدل ترجمه برای گفتار ساخته شده و از پس آواز برنمی‌آید. در قسمت‌های
موسیقی دکمهٔ **قرمز** را بزنید تا ترجمه خاموش شود و صدای اصلی کامل پخش شود.

### لب‌خوانی با تصویر جور نیست

با دکمهٔ **سبز** تأخیر را یکی‑دو ثانیه کم یا زیاد کنید.

## زیرنویس

| مشکل | راه‌حل |
|---|---|
| چیزی پیدا نمی‌شود | کلید OpenSubtitles یا SubDL و گزینهٔ *Subtitle Language* را بررسی کنید |
| زود یا دیر می‌آید | کلیدهای `2` و `8` در حین تماشا، هر بار نیم ثانیه |
| هرچه جلوتر می‌رود بیشتر جلو/عقب می‌افتد | نرخ فریم اشتباه است: کلیدهای `4` و `6` |
| اصلاً نشان داده نمی‌شود | کلید `0` زیرنویس را روشن/خاموش می‌کند |

---

## بوکه

| مشکل | راه‌حل |
|---|---|
| کانال‌های بوکه پخش نمی‌شوند | بعد از ساختن بوکه، انیگما۲ ری‌استارت نشده. صفحهٔ Bouquets وضعیت resolver را نشان می‌دهد. |
| کانال‌های بوکه ترجمه ندارند | گزینهٔ *Translated audio in bouquets* را روشن کنید. آن وقت زپ چند ثانیه بیشتر طول می‌کشد. |
| بعد از نصب مجدد بوکه خالی است | از منوی Bouquets دوباره خروجی بگیرید. |

---

## خواندن لاگ‌ها

همهٔ لاگ‌ها در `/tmp` هستند، پس با هر ری‌استارت پاک می‌شوند.

| فایل | چه چیزی را ثبت می‌کند |
|---|---|
| `/tmp/piip_dub.log` | ترجمه: اتصال، زمان‌بندی، عقب‌افتادگی، بافرها |
| `/tmp/piip_engine.log` | استریم منبع: کانال، ffmpeg، ری‌استارت‌ها |
| `/tmp/piip_resolver.log` | تبدیل کانال بوکه به استریم |
| `/tmp/piip_ui.log` | صفحه‌ها |

دستورهای مفید با SSH:

</div>

```bash
tail -40 /tmp/piip_dub.log
```

```bash
grep "Audio flow" /tmp/piip_dub.log | tail -5
```

```bash
grep -iE "error|failed|retrying" /tmp/piip_engine.log | tail -20
```

<div dir="rtl">

**قبل از اینکه لاگ را جایی بفرستید، آن را از نظر آدرس و رمز اشتراکتان بررسی
کنید.** برنامه کلید API را پنهان می‌کند، اما آدرس یک استریم می‌تواند نام کاربری
و رمز شما را داشته باشد.

## شروع دوباره از صفر

اگر برنامه رفتار عجیبی دارد و هیچ راهی جواب نداد:

</div>

```bash
dpkg -r enigma2-plugin-extensions-piip
```

```bash
rm -f /etc/enigma2/piip_*.json /etc/enigma2/userbouquet.piip_*.tv
```

<div dir="rtl">

بعد بسته را دوباره نصب کنید. کلید API شما در `/root/apikey.txt` از این کار جان
سالم به در می‌برد.
